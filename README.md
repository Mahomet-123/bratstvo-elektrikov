# Братство Электриков — учёт объектов

Приложение для бригады электриков: расчёт работ по прайсу, журнал работ по дням, закупки материалов с фото накладных, офлайн-записи с очередью отправки, отчёты и кабинет для клиента.

## Что внутри

| Часть | Где живёт | Назначение |
|---|---|---|
| PWA-приложение | `public/` | Статика без сборки: ставится на телефон, работает офлайн. Хостинг — любой статический (EdgeOne Pages, GitHub Pages, Timeweb) |
| Бэкенд | `backend/` | Google Apps Script, привязан к рабочей таблице: REST для приложения, кабинет клиента, заготовка бота |
| Прайс | `backend/seed/price.json` | 204 позиции из прайс-листа «Братство Электриков ЧР, июнь 2026» |

## Листы рабочей таблицы

- **Объекты** — реестр: номер, имя, имя листа, клиент, статус, токен кабинета
- **Прайс** — справочник работ (разделы ①–⑧, единицы, цены)
- **Пользователи** — Руководитель + мастер 1…50; коды доступа выдаёт Руководитель в приложении
- **Посещения** — журнал входов (кто и когда заходил)
- **Статусы** — снимки очереди отправки с каждого устройства
- **NNN_Имя объекта** — на каждый объект свой лист с блоками РАСЧЁТ / ДЕНЬ / ЗАКУПКА

## Как запускается офлайн-режим

1. Запись сразу пишется в очередь в телефоне (IndexedDB)
2. Если есть сеть — уходит сразу; если нет — копится
3. В шапке индикатор: «Всё отправлено» / «N в очереди» / «Ошибка»
4. При появлении интернета очередь уходит сама, с повторами (1 → 5 → 15 мин)
5. Тап по индикатору — ручная отправка
6. Повторная отправка одной и той же записи дублем не считается (у каждой свой ID)

## Деплой

### Основной путь: npm-скрипты через clasp

**Один раз:**

```bash
npm install          # ставит clasp локально (глобально ничего не нужно)
npx clasp login      # если clasp ещё не авторизован на этой машине
```

Создать проект Apps Script и привязать к таблице. Два способа:

- **Терминал:** `npx clasp create --parentId 1UHSlJOVzJaq-cIdi-JRAxxr__-gOsebIacy0iiV288w --type sheets --title "Братство Электриков — API"` — команда сама впишет `scriptId` в `.clasp.json`
- **Браузер:** таблица → **«Расширения» → «Apps Script»** → слева **«Настройки проекта»** → скопировать **«Идентификатор скрипта»** → вставить в `.clasp.json` вместо `ВПИШИ_SCRIPT_ID_ИЗ_APPS_SCRIPT`

**Дальше — одной командой:**

```bash
npm run gas:push     # clasp push --force → 14 файлов из backend/ отдельными файлами
```

В таблице (меню **«Братство Электриков»**): «Инициализировать структуру» → «Загрузить прайс из seed» — листы, профили (Руководитель / `0000`), 204 позиции прайса.

```bash
npm run gas:deploy   # clasp deploy → адрес https://script.google.com/macros/s/XXX/exec
npm run gas:open     # открыть Apps Script в браузере
```

Адрес из `gas:deploy` вписать в `public/js/config.js` (`API_URL`).

### Вариант без терминала: установщик в браузере

1. Таблица → **«Расширения» → «Apps Script»**
2. Открой `Установщик.gs` в корне проекта (Блокнот/VS Code), скопируй **весь файл** и замени им содержимое `Код.gs`. Сохрани
3. **«Сервисы» → «+» → «Apps Script API» → «Добавить»** (один раз)
4. Выполни функцию **`installAll`** → обнови страницу (F5): появятся **14 отдельных модулей** (Config, Seed, Sheets, Users, Visits, Objects, Records, Prices, Photos, Archive, Cabinet, Router, Bot, Code), установщик удалит сам себя
5. Выполни `ensureStructure`, затем `seedPricesFromBackend`
6. Опубликуй: **«Настроить развёртывание» → «Новое развёртывание» → «Веб-приложение»**, выполнять от имени «Я», доступ **«Все»** → «Развернуть» → скопируй адрес `.../exec`

Установщик пересобирается: `npm run installer`. Он лежит в корне проекта и **не** заливается clasp (в `backend/` только рабочие модули + `seed/price.json`).

**Фронтенд:**

1. Впиши адрес API в `public/js/config.js` (`API_URL`)
2. Папку `public/` выложи на статический хостинг:
   - **Netlify Drop**: app.netlify.com/drop (бесплатно) — перетащил папку, получил ссылку
   - или скажи «деплой» — выложу через EdgeOne Pages
3. На телефоне: открой ссылку → «На экран Домой». Вход — **Руководитель / 0000**, код сразу смени

### 2. Фронтенд

Вписать адрес веб-приложения в `public/js/config.js` (`API_URL`), залить папку `public/` на статический хостинг. На телефоне: открыть сайт → «Поделиться → На экран Домой».

## Обновление прайса

Прислать новый PDF — я переразбираю его и обновляю seed:

```bash
npm run seed        # parse-price-pdf.py + build-seed.py
npx clasp push
# в таблице: «Братство Электриков → Загрузить прайс из seed»
```

Старые цены остаются в листе «Прайс» с датой загрузки — история сохраняется.

## Правило 203 и итоги

Снабжение материалом — **+10% от стоимости материалов, минимум 1500 ₽** (позиция 203 прайса). Учитывается автоматически в отчёте и кабинете клиента.

## Клиенту

- **PDF**: вкладка «Отчёт» → «Печать / сохранить PDF» (печать из браузера телефона)
- **Кабинет**: временная ссылка (сокращение через clck.ru), живёт до закрытия объекта. Открывается **внутри приложения** (`#/cabinet/id/токен`, без входа) — без промежуточной страницы Google; после закрытия показывает «Объект закрыт»

## Закрытие объекта и архив

Закрытие копирует лист объекта в таблицу **«Архив ГОД»** и убирает его из рабочей. Доп. работы по тому же объекту — кнопка «Возобновить работы»: лист возвращается со всей историей. Фото накладных не переезжают — лежат в Drive по идентификаторам.

## Этап 2 (после базового запуска)

- Telegram-бот: `backend/Bot.gs` — напоминания «неотправленные записи», «по объекту день без записи», «объект закрыт». Нужен токен от @BotFather: свойства скрипта → `BOT_TOKEN`, затем `setWebhook` и триггер по расписанию
- Редактирование и удаление записей (сейчас — добавление с пометками, по политике «только добавляем»)

## Лимиты бесплатного Google (о котором помним)

- ~90 минут выполнения скриптов в сутки, 15 ГБ диска
- Фото сжимаются в WebP ~300 КБ в телефоне до отправки — этого хватает на десятки тысяч фото
- При 10+ объектах в месяц и бригаде 5+ человек пора обсуждать переход на российский сервер

## Разработка

```bash
npm run check      # проверка синтаксиса всех файлов
npm run test:e2e   # полный прогон сайта в headless Chrome: вход, расчёт, закупки с фото, офлайн, кабинет (25 проверок)
npm run seed       # пересборка прайса из PDF
```

Для `test:e2e` нужен запущенный локальный сервер из `public/` (например `python -m http.server 8080`) и системный Chrome. Диагностика одной страницы любого адреса: `node scripts/test-site.js <url>`. Обслуживалка прав доступа старых фото: `node scripts/fix-photos-sharing.js`.

Структура кода — по стандарту: модули с шапками и JSDoc, 2 пробела, БЭМ, изолированные стили компонентов, кэш и ленивая загрузка.
